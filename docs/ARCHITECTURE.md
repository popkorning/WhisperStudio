## Процессы

```text
 окно (pywebview, WebView2)      MCP-клиент (агент)        командная строка
          │ HTTP 127.0.0.1                │ stdio JSON-RPC            │
   server.py (http.server)          mcp_server.py               cli.py
          └───────────────┬───────────────┴─────────────┬─────────────┘
                options.py / store.py / jobs.py   (лёгкие: stdlib, без numpy/torch)
                          │  HOME\queue\job-*.json
                     worker.py  ── один на машину (worker.lock), модели держит между задачами,
                          │        выходит через 120 с простоя
                    pipeline.py ── engine.py (быстро) или ensemble.py (максимум)
```

- **UI** (`app.py` + `server.py` + `web/`): окно открывается сразу с заставкой и переключается на
  интерфейс, когда поднят локальный HTTP-сервер. Фронтенд — vanilla JS, wavesurfer.js, шрифт Inter.
- **MCP** (`mcp_server.py`): свой JSON-RPC на стандартной библиотеке, протоколы 2024-11-05…2025-11-25.
  Ответы рассчитаны на контекст языковой модели: компактный текст, длинное — страницами, варианты
  моделей — только отличия.
- **CLI** (`cli.py`): `python -m whisper_studio <команда>`; `transcribe` по умолчанию тоже идёт
  через воркер (`--here` — посчитать в этом процессе).
- **Воркер** (`worker.py`, `jobs.py`): очередь — файлы задач; файл удаляется только после конца
  задачи, так что очередь переживает перезапуск. Тяжёлое (Whisper, выравнивание, спикеры,
  LLM-вычитка) идёт только здесь, чтобы окно и MCP стартовали за доли секунды и не держали GIL.

Правило лёгких модулей: UI-сервер, MCP-сервер, `options.py`, `store.py`, `jobs.py`, `settings.py`
не импортируют numpy и torch. Каждый лишний импорт — секунды старта на холодном диске.

## Данные

Всё в `WHISPER_STUDIO_HOME` (по умолчанию `%LOCALAPPDATA%\WhisperStudio`), раскладка — в README.

Запись — папка `library\<id>\`:

| Файл | Что |
|---|---|
| `doc.json` | документ: `id, title, source_path, status, progress, stage, error, meta, options, language, duration, speakers, segments, edited, rev` |
| аудио | проигрываемая копия исходника |
| `peaks.json` | волна для плеера |
| `hypotheses.json` | сырые гипотезы каждой модели по кускам (`hypotheses-1/2.json` у стерео) |
| `voices.npz` | эмбеддинги и активность спикеров: переразметка без пересчёта звука |
| история | снимки для отмены правок |

Сегмент: `id` (`g12`), `start`, `end`, `text`, `speaker`, `words` = `[{w, s, e, p, spoken?, edited?}]`,
`alts` = `[{model, text}]` (текст каждой модели на этом отрезке), `lang`, `flags` (например,
подозрение на галлюцинацию), `verified` у эталона. Все изменения идут через `store.py`: каждая правка
оставляет снимок для отмены, при правке текста таймкоды неизменённых слов сохраняются, новых —
интерполируются.

`settings.json` — умолчания (`language: ru`, `mixed: true`, `num_speakers: 2`, `quality: max`,
`profile: balanced`, `model: auto`), адрес OpenAI-совместимого LLM для вычитки и раздел `speed`.
`dictionary.json` — термины, правила замены, абзац контекста. Запись в оба — под файловой блокировкой
(окно, MCP и CLI пишут одновременно) с проверкой версии.

## Конвейер аудио

`pipeline.process`:

1. **Аудио** (`audio.py`, PyAV): 16 кГц моно float32, без AGC и без вырезания тишины. Стерео-звонок по
   флагу делится на два канала = два спикера. Фильтр гула 80 Гц — только по флагу. Волна, длительность.
2. **Язык** записи: если не задан — определение языка Whisper.
3. **Распознавание** — `engine.py` (быстрый режим) или `ensemble.py` («Максимум»), ниже.
4. **Числа цифрами** (`asr/itn.py`) и **правила замены словаря** (`store.apply_rules_to_segments`).
5. **Таймкоды слов** (`align.py`): wav2vec2 CTC forced alignment по языку каждого сегмента (немецкие
   фразы в русской записи получают немецкий выравниватель). Текст не меняется. Буквы, которых нет в
   алфавите выравнивателя (латиница в русском, цифры), становятся «джокерами» по числу звуков, чтобы
   слово получило своё время, а не отдало его соседям.
6. **Спикеры** (`diarize.py`, `diarize_ort.py`), ниже.
7. `store.finalize`: спикеры по порядку появления, сегменты, сохранение.

### Быстрый режим (`engine.py`)

Одна модель Whisper под язык (`models.AUTO_WHISPER`: ru → `ru-large-v3`, de → `de-turbo`, иначе
`large-v3`), faster-whisper, последовательное длинное декодирование окнами 30 с. Beam 5, best_of 5,
температуры 0…1, compression 2.4, logprob −1, no_speech 0.6. Мягкий VAD (порог 0,35, паузы ≥ 2 с,
запас 400 мс) только против галлюцинаций на длинных паузах, `hallucination_silence_threshold=2`,
чёрный список фантомных фраз RU/DE/EN. Подозрительное помечается флагом, а не удаляется. Словарь идёт
в `initial_prompt`, без контекста — в `hotwords`. Профили: «Универсальный» (VAD + контекст), «Чистая
речь» (без VAD), «Совещание, шум» (VAD, без контекста, hotwords).

### Режим «Максимум» (`ensemble.py`)

1. **Куски.** Silero VAD (из faster-whisper) → речевые отрезки склеиваются в куски ≤ 25 с (новый кусок
   после паузы > 2 с, перекрытие 1,5 с на разрезе внутри речи). Все модели слушают одни и те же куски,
   независимо, без переноса контекста: один плохой кусок не тянет за собой следующие.
2. **Язык куска** — по language-ID Whisper и по алфавиту текста large-v3. В смешанном режиме
   (`mixed`, ru + de) кусок бывает русским, немецким или смешанным.
3. **Участники** (`MEMBERS`), строго по одному на GPU:

   | Участник | Движок | Где | Язык | Вес |
   |---|---|---|---|---|
   | `large-v3` | CTranslate2 fp16 | GPU | сам определяет; он же даёт язык кусков | 1,0 |
   | `ru-large-v3` | CTranslate2 fp16 | GPU | только русские куски | 1,0 |
   | `de-turbo` | CTranslate2 fp16 | GPU | только немецкие | 1,0 |
   | `qwen3-asr` | transformers fp16, sdpa, пачки по 4 | GPU | язык куска, кроме смешанных; без подсказки | 1,0 |
   | `gigaam-v3` | onnx-asr, RNN-T | CPU | только русские | 1,2 |
   | `canary-v2` | onnx-asr, int8 | CPU | только немецкие | 0,8 |
   | `t-one` | onnx-asr, CTC, пачки по 8 | CPU | только русские | 0,5 |
   | `de-check` | de-turbo, только температура 0 | GPU | немецкий проход как улика, без голоса | 0 |

   Сырые результаты пишутся в `hypotheses.json` после каждой модели: прерванная задача продолжает с
   недостающей, а слияние пересчитывается без GPU (`ws redoubt`). Если посреди записи кончается
   видеопамять, модель перезагружается и кусок пробуется ещё раз; не вышло — пропускается только он.
4. **Слияние (ROVER).** Гипотезы выравниваются в сеть путаницы (расстояние правки по нормализованным
   словам плюс время). Каждый слот решается взвешенными голосами: вес модели × её уверенность в
   слове; «здесь ничего не сказано» — тоже голос (0,75 от голоса за слово). Слова сравниваются по
   ключам (`asr/text.py`): регистр, пунктуация и ё не важны, «25-го» и «двадцать пятого» — одно и то
   же. Кириллическое написание незнакомого слова отдаёт 0,85 своего голоса похожему по звучанию
   немецкому слову («вонунг» → Wohnung). Латинское слово, написанное буква в букву как термин
   словаря, получает вдвое больше голосов против кириллицы, которая не является русским словом.
   Написание победителя (цифры, регистр, знаки) берётся у модели по порядку `SURFACE`.
5. **Перепроверка.** Слова, которых нет в русском словаре (pymorphy3), ищутся в глоссарии и в немецкой
   гипотезе de-check в то же время.
6. **Термины по звучанию** (`terms.py`), ниже.
7. **Сомнение** (`_doubt`): p слова = согласие моделей минус штрафы — похоже на термин или его
   начало 0,5; не по-русски 0,5; модели слышали разные числа 0,2; даже самая уверенная из голосовавших
   не уверена 0,1; голосовали две модели или меньше 0,05. p < 0,35 — подсветка, p < 0,5 — пунктир.
8. **Числа цифрами** (`asr/itn.py`) в тексте и в `alts`, сказанное — в `w["spoken"]`.
9. Сегменты в формате быстрого режима плюс `alts` и `lang`.

### Термины по звучанию (`terms.py`)

Восстанавливает немецкие слова внутри русской речи, которые все модели записали кириллицей. Только
CPU, без повторного распознавания.

- **Список терминов**: глоссарий записи, словарь проекта (составные дают и части: Hotel-Anmeldung
  → Anmeldung) и выученный список `terms-learned.json` (`tools/build_terms.py`: немецкие
  существительные из реплик, исправленных вручную; эталоны исключены).
- **Кандидаты**: 1–3 слова слияния в русской речи; русское окончание последнего слова отрезается и
  сохраняется («Wohnungу»). Предлог, слитый с термином («повонунг»), отделяется.
- **Звук**: общий фонетический скелет для кириллицы и немецкого написания (`asr.text.phon`), с бонусом
  за общее начало: русское ухо держит начало немецкого слова и коверкает конец.
- **Улики**: что слышали другие модели в то же время. В счёт идёт только не-русское услышанное
  (незнакомое pymorphy слово или латиница); модель, написавшая то же, что слияние, — не улика.
  Настоящие русские слова заменяются только при сильном звуке и улике. Термин, найденный в записи
  уверенно, во втором проходе требует меньше («одна беседа — одна тема»). Латинское слово среди
  латинских не трогается.

### Спикеры (`diarize.py`, `diarize_ort.py`, `onnx_torch.py`)

Тот же конвейер, что `OfflineSpeakerDiarization` из sherpa-onnx, перенесённый на numpy/onnxruntime:

1. сегментация pyannote 3.0 (onnxruntime, CPU): окна 10 с со сдвигом 1 с, powerset на 3 локальных
   спикера;
2. kaldi-fbank 80 (как у sherpa) по каждой паре «окно, локальный спикер»;
3. эмбеддинги WeSpeaker ResNet293 — torch fp32 на GPU: граф ONNX читается своим мини-парсером protobuf
   и исполняется операторами torch (18 типов узлов); без CUDA — onnxruntime на CPU, при ошибке — sherpa-onnx;
4. complete linkage по косинусу (scipy), порог 0,5; кадры → отрезки;
5. `refine` под заданное число спикеров: маленький сырой кластер идёт целиком к ближайшему голосу;
6. спикер — каждому слову; слово вне отрезков или в перекрытии решает мягкая активность сегментации
   (сохраняется в `voices.npz`).

`rediarize` пересчитывает спикеров с другим числом мгновенно, из `voices.npz`, и не трогает
закреплённые вручную реплики.

## Вычитка (`llm.py`, `mcp_server.py`)

Один и тот же пакет вычитки двумя путями: в приложении — запрос к OpenAI-совместимому серверу из
`settings.llm`; через MCP — агент получает `proofread_pack` (инструкции, словарь, контекст, текст с
пометками ⟨…⟩ и отличиями других моделей) и возвращает только изменённые реплики `apply_corrections`.
Ответ локальной модели в приложении проходит рамки (`llm.refused`): нет новых чисел, нет новых слов
сверх услышанного моделями и словаря, правка не больше заданной доли реплики (если это не вариант
одной из моделей целиком). На эталонах вычитка запрещена. Правки ИИ помечены ✦ и отменяются одним шагом.

## Эталон и оценка (`gold.py`)

Эталон — записи, выверенные на слух ([GOLD.md](GOLD.md)). Оценка идёт по сохранённым гипотезам, без
GPU, в отдельном процессе: WER каждой модели и слияния, абляция (без каждой модели), трудные слова
(числа, латиница, имена, термины), точность и полнота пометок сомнения, по желанию — подбор весов с
проверкой на записи, не участвовавшей в подборе. Итог — `HOME\gold\latest.json`, история —
`history.jsonl`. Веса в коде сами не меняются.

## Скорость

- Модели по одной на GPU, порядок задан так, чтобы каждая грузилась один раз; de-turbo идёт последней
  и остаётся загруженной для de-check.
- `prefetch.py`: фоновый поток читает файлы следующих моделей в кэш ОС (до 6 ГБ вперёд), на время
  загрузки любой модели — пауза.
- `asr/gpu.py`: перед загрузкой ждать свободную видеопамять, а не падать.
- Необязательные `parallel_cpu` (ONNX-участники в отдельном потоке рядом с GPU), `batch` (несколько
  записей «модель за моделью»), `early_voices` (голоса спикеров в отдельном CPU-процессе).

## Интерфейс

Спокойное окно для вычитки: сайдбар (поиск, библиотека, очередь, эталон, словарь, модели), тулбар
(название, «Проверка N» с переходом по сомнительным словам, поиск, экспорт), колонка текста до 720 px
с репликами по спикерам, инспектор (фрагмент и варианты моделей, спикеры, сведения о файле) и плеер
с волной и полосой спикеров. Цвет спикера один и тот же везде. Светлая и тёмная темы,
`prefers-reduced-motion`, `forced-colors`, масштаб 100–200%, минимальное окно 760×480.
В документе-эталоне клавиши меняют смысл: Enter — «верно на слух» и к следующему, E — править,
Ctrl+/ — «не разобрать»; варианты моделей по умолчанию скрыты, чтобы не подсказывать слушателю.
