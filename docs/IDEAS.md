# Идеи на потом

## Память о прошлых разговорах (эмбеддинги)

Идея: весь текст, прошедший через транскрибацию, векторизовать маленькой моделью эмбеддингов и
подключать эту базу при новой транскрибации и при вычитке. Так модели «знают», о чём обычно речь, и их
вероятности смещаются под свои разговоры: люди, места, числа, темы.

Где это может работать:

1. **Подсказка распознаванию.** Быстрый первый проход → поиск похожих прошлых фрагментов →
   из них собрать подсказку: Whisper `initial_prompt`/hotwords, контекст Qwen3-ASR (принимает
   до ~10k токенов текста). Второй проход — только по спорным кускам. Короткая подсказка с
   редкими словами в конце работает лучше длинного списка.
2. **Голос «памяти» в слиянии.** Если вариант слова встречался в выверенных прошлых
   транскриптах рядом с похожим контекстом, он получает небольшой голос, как сейчас глоссарий,
   только выученный, а не ручной.
3. **Вычитка.** LLM получает примеры прошлых правок пользователя в похожих местах (few-shot).
4. **Поиск по смыслу** по всем транскриптам: EmbeddingGemma-308M или Qwen3-Embedding-0.6B
   плюс текущий полнотекстовый поиск.
5. **Своя языковая модель.** Из выверенных текстов — маленькая n-граммная модель (KenLM) или
   дообучение, чтобы вероятности слов были «свои».

Похожее в литературе: contextual biasing, retrieval-augmented ASR, kNN-LM / kNN-CTC.

Главный риск — петля ошибок: если в базу попадают невыверенные транскрипты, ошибки начнут
подтверждать сами себя. В базу — только текст, исправленный на слух, или хотя бы слова с высоким
согласием моделей. Мерить на эталоне (`tools/asr_eval.py`) до и после.

### Что проверили ([DECISIONS.md](DECISIONS.md))

- **Подсказка распознаванию** (п. 1) — отклонено: термины в prompt Whisper и контексте Qwen3
  ухудшают эталон (34 → 44…65 ошибок), модели подгоняют русскую речь под список (DECISIONS, п. 4.2).
  Даже подсказка из одного правильного термина почти не помогает (п. 4.7).
- **Голос памяти** (п. 2) — отклонено: сужать поиск терминов до найденных в похожих прошлых
  отрывках (эмбеддинги multilingual-e5-small) бесполезно — эталон 34 → 34, ложных замен 23 → 21
  (DECISIONS, п. 5; `memory.py`, выкл.).
- **Своя языковая модель** (п. 5) — малые LLM как голос на спорных местах (Qwen3-0.6B, 1.7B,
  RuModernBERT) хуже при любом весе (DECISIONS, п. 7.1; `lm_vote.py`, выкл.). KenLM на выверенных
  текстах не пробовали: выверенного текста пока мало.
- **Что сработало вместо этого** — восстановление немецких терминов по звучанию после слияния
  (`terms.py`): список терминов из словаря, своих заметок и ручных правок, слияние 7,0% → 5,3%.
- Не проверяли: вычитка с примерами прошлых правок (п. 3), поиск по смыслу (п. 4).

## Остальное

- Фонемный распознаватель без языка (ZIPA, POWSM, wav2vec2-espeak) как голос «термин или русское
  слово» на сомнительных местах; «пул» трудных слов — поиск по образцу (DTW по фонемам на
  подтверждённых кусках и озвучке TTS).
- Модели с подсказками слов (parakeet / canary в NeMo) для повторного распознавания сомнительных мест.
- Обученный выбор слова в слиянии (лес, бустинг) — когда эталона станет достаточно, чтобы проверить
  честно: потолок на текущих моделях ~2% слов.
- Дообучение на синтетике редких терминов.
